# Учёт торговли и Excel

В админке откройте «Себестоимость». Вкладка «Обзор» показывает текущее состояние мастерской, «Реестр остатков» — товары построчно, «Расходы» — журнал затрат, «Калькуляции» — существующий расчёт материалов и себестоимости.

## Как читать показатели

- **Доступно** — количество готовых свечей, которое ещё можно заказать. Оформленные заказы уже уменьшили его; резерв отображается отдельно и повторно не вычитается.
- **Потенциальная выручка** — доступный остаток × текущая цена товара. Включает скрытые товары и черновики; сумма по опубликованным позициям указана отдельно.
- **Себестоимость остатка** — остаток × текущая себестоимость по связанной калькуляции.
- **Ожидаемая валовая прибыль** — потенциальная выручка минус рассчитанная себестоимость только для товаров с однозначной заполненной калькуляцией. Не является чистой прибылью, оплатой или прогнозом спроса.
- **Нет калькуляции / несколько калькуляций / не заполнен состав** — стоимость неизвестна, а не равна нулю. В Excel соответствующие числовые ячейки пусты. Предупреждение показывает, сколько свечей и выручки не включено в оценку прибыли.
- **Выполненные заказы** — стоимость заказов со статусом «Выполнен», созданных за выбранный период. В приложении нет отдельного подтверждения оплаты; этот показатель нельзя считать поступлениями денег.
- **Расходы** — записи, внесённые вручную. Они не вычитаются повторно из валовой прибыли, поскольку закупленные материалы могут уже входить в себестоимость.

Заказы отбираются по дате создания в часовом поясе Москвы, расходы — по указанной дате. Границы периода включаются. Остатки всегда показываются на момент загрузки отчёта. Для полного списка выберите «За всё время». После изменения товаров или калькуляций нажмите «Обновить».

## Журнал расходов

Укажите дату, категорию (можно свою), сумму и описание. Сумма должна быть положительной, максимум два знака после запятой. Запись можно изменить или удалить из активного журнала; в базе удаление сохраняет архивную запись. Если другой администратор уже изменил запись, система предложит обновить список и не затрёт чужие изменения. Ошибка сохранения оставляет введённый текст.

## Выгрузки

| Кнопка | Листы XLSX |
| --- | --- |
| Вся книга Excel | Все 10 листов ниже |
| Реестр в Excel / Остатки в Excel | Сводка, Остатки |
| Себестоимость в Excel | Сводка, Калькуляции, Состав калькуляций, Материалы, История себестоимости |
| Заказы в Excel | Сводка, Заказы, Позиции заказов, Выполнено по формам |
| Расходы в Excel | Сводка, Расходы |

В реестре экспортируются результаты текущего поиска и отбора. Выгрузки из обзора и журнала учитывают применённый период, кнопки в основных разделах «Заказы» и «Остатки» выгружают всё. На листе «Сводка» указан охват. История себестоимости содержит сохранённые снимки; её значения не пересчитываются по новым ценам материалов.

Файлы содержат обычные числовые ячейки, денежный формат, автофильтры и закреплённую первую строку. Пользовательские строки, в том числе начинающиеся с `=`, экспортируются как текст. Доступ к файлам есть только у авторизованного администратора; листы заказов содержат сведения покупателей.

## Устройство и проверки

Чистые вычисления: `lib/trade-report.ts`; чтение согласованного снимка PostgreSQL и журнал расходов: `lib/server/trade-reports.ts`; XLSX: `lib/server/trade-workbook.ts`. Миграции запускаются через `prepareCosting()` и не меняют существующие цены, остатки, заказы или связи калькуляций.

- `GET /api/admin/reports?from=YYYY-MM-DD&to=YYYY-MM-DD` — обзор, реестр и журнал.
- `POST /api/admin/reports` — `action: expense` (создать/изменить) или `remove-expense` (архивировать); изменения требуют текущие `id` и `version`.
- `GET /api/admin/reports/export?kind=all|inventory|costing|orders|expenses` — XLSX; поддерживает `from`, `to`, а для реестра `q` и `stock`.

Сначала проверяется административная сессия. Ответы не кешируются. Модуль ExcelJS используется только на сервере. Отчёт читает одну транзакционную версию данных и не резервирует товар.

Проверки: `node --test tests/trade-report.test.mjs`, `npm run test:ui`, `node --test tests/reports-http.test.mjs`. HTTP-тестам нужны production-сборка и **изолированная** PostgreSQL через `TEST_DATABASE_URL`; рабочую базу использовать запрещено. Проверка публикации читает публичные JS и проверяет 401 без входа и без записи данных.
