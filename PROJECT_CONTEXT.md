## Рабочее окружение

- Рабочий сайт: https://tixo-mia-ashinoff.mia0.amvera.tech/
- Админка: https://tixo-mia-ashinoff.mia0.amvera.tech/admin
- Репозиторий: `ashinoff/TIXO`, публикационная ветка `main`.
- Next.js / React / TypeScript, Node.js 22, PostgreSQL через `pg`; версии в package.json.
- Docker, standalone, порт 3000; данные из DATABASE_URL, загруженные изображения на постоянном диске `/data/uploads`.
- Не менять секреты, реальные заказы, остатки, идентификаторы справочников или диск `/data` при обновлении кода.
- Старый адрес `tixo-ashinoff.amvera.io` и прототип ChatGPT Sites не являются текущим доменом.

## Калькуляции: привязка к нескольким товарам

Причина исходного дефекта: API возвращал PostgreSQL BIGINT-идентификаторы строками без нормализации, а select сравнивал их с Number(value) строгим равенством. Поэтому товар не находился и выбор сбрасывался. Все ID материалов, расчётов, товаров и истории теперь явно нормализуются в числа; клиент также принимает старые строковые ответы.

- `app/api/admin/costing/route.ts`: защищённый административный API, миграции и транзакционное сохранение калькуляций.
- `app/admin/cost-calculator.tsx`: калькулятор, прайс, поиск и множественный выбор товаров, история.
- `app/admin/cost-calculator.css`: стили новых элементов в существующей теме админки.
- Связи хранятся в `costing_recipe_products(recipe_id, product_id)` с составным первичным ключом. Цены, публикация и остатки товаров не переписываются.
- `costing-product-links-v1` однократно переносит старые `costing_recipes.product_id`. История и сами рецептуры сохраняются. Снятые связи не создаются заново при последующих запросах.
- Старое поле product_id оставлено для совместимости: ID при одной связи, null при нуле или нескольких. Основной контракт: product_ids как массив ID.
- Старый клиент с единственным product_id не может затереть множественные связи: получает 409 и просьбу обновить страницу.
- version / expected_version защищают редактирование и удаление из устаревшей вкладки. Сохранение связей, состава, версии и снимка истории выполняется одной транзакцией.
- Архивный товар, уже связанный с расчётом, показывается с отметкой и может остаться в нём. Новые привязки к архивным товарам запрещены.
- Поиск работает по названию, форме, цвету, декору, аромату и номеру. Есть «Выбрать найденные», «Снять все» и «Только выбранные».
- Прибыль и маржа связанных товаров рассчитываются отдельно по цене каждого товара. Расчётная цена сценария не меняет цены каталога и не перезаписывается выбором товаров.
- После сохранения редактор остаётся на том же расчёте и получает сохранённые ID/версию. После ошибки сохранения или удаления черновик не очищается.
- В новые снимки истории включены связанные товары и их цены на момент сохранения. Старые снимки не пересчитываются.

## Проверки

Стандартный набор: `npm run lint`, `npm run test:catalog`, `npm run test:ui`, `npm run build:amvera`, `npm run test:http`.

Новые проверки: `node --test tests/costing-ui.test.mjs` и `node --test tests/costing-http.test.mjs`. HTTP-проверка требует production-сборку и отдельную PostgreSQL в TEST_DATABASE_URL. Никогда не направляйте тесты на рабочую базу.

UI-проверки покрывают строковые BIGINT ID, выбор нескольких товаров, сохранение/повторное открытие, независимые цены, поиск, массовый выбор, ошибки и повторный клик. HTTP-проверка покрывает старую схему, миграцию связей, numeric ID, дедупликацию, архивные товары, конфликты версий, неизменность снимков и сохранность товаров. Все эти команды включены в `.github/workflows/catalog.yml`.

23 октября 2026: для кода `13efd976` GitHub Actions [40008595913](https://github.com/ashinoff/TIXO/actions/runs/40008595913) успешно выполнил каталог, lint, прежние UI-тесты, новые UI-тесты калькулятора, production-сборку, прежние HTTP-тесты и новый HTTP-сценарий с PostgreSQL. Геометрия нового блока отдельно проверена в изолированном HTML-макете Chromium на 320/393/760/1440 px; устранено переполнение строки материалов на 320 px. Это не заменяет авторизованную проверку рабочей админки. Реальные заказы и данные при проверке не менялись.

## Публикация и Amvera

Успех Actions и обновление main сами по себе не доказывают развёртывание Amvera. Владелец ранее переподключил репозиторий после ошибки webhook `failed to connect to host`.

После успешных тестов main отдельное задание `Confirm admin on Amvera (read-only)` запускает `scripts/check-costing-publication.mjs`. Оно читает только публичную страницу `/admin` и её статические JS-файлы на текущем домене, проверяя наличие нового блока множественных привязок. Нет авторизации, записи заказов или изменения рабочих данных. Число попыток ограничено; недоступность домена или старая версия дают отдельную ошибку публикации, не маскируются зелёной сборкой. Это проверка доставки нового интерфейса, а не подтверждение выполнения миграции в рабочей базе.

Фактические результаты проверять для актуального SHA/запуска и нужного домена. Не обещать публикацию без проверки. Историю текущей правки и дальнейшее подтверждение main см. [PR №6](https://github.com/ashinoff/TIXO/pull/6).
