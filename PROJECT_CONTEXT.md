Проверка опубликованных страниц проводится отдельно от локальных тестов.

## Калькуляции: привязка к нескольким товарам

Причина исходного дефекта: API возвращал PostgreSQL BIGINT-идентификаторы строками без нормализации, а select сравнивал их с Number(value) строгим равенством. Поэтому товар не находился и выбор сбрасывался. Все ID материалов, расчётов, товаров и истории теперь явно нормализуются в числа; клиент также принимает старые строковые ответы.

- `app/api/admin/costing/route.ts`: защищённый административный API, миграции и транзакционное сохранение калькуляций.
- `app/admin/cost-calculator.tsx`: калькулятор, прайс, поиск и множественный выбор товаров, история.
- `app/admin/cost-calculator.css`: стили новых элементов в существующей теме админки.
- Связи хранятся в `costing_recipe_products(recipe_id, product_id)` с составным первичным ключом. Цены, публикация и остатки товаров не переписываются.
- `costing-product-links-v1` однократно переносит старые `costing_recipes.product_id`. История и сами рецептуры сохраняются. Снятые связи не создаются заново при последующих запросах.
- Старое поле product_id оставлено для совместимости: ID при одной связи, null при нуле или нескольких. Основной контракт: product_ids как массив ID.
- Старый клиент с единственным product_id не может затереть множественные связи: получает 409 и просьбу обновить страницу.
- version / expected_version защищают редактирование и удаление из устаревшей вкладки. Сохранение связей, состава, версии и снимка истории выполняется одной транзакцией.
- Архивный товар, уже связанный с расчётом, показывается с отметкой и может остаться в нём. Новые привязки к архивным товарам запрещены.
- Поиск работает по названию, форме, цвету, декору, аромату и номеру. Есть «Выбрать найденные», «Снять все» и «Только выбранные».
- Прибыль и маржа связанных товаров рассчитываются отдельно по цене каждого товара. Расчётная цена сценария не меняет цены каталога и не перезаписывается выбором товаров.
- После сохранения редактор остаётся на том же расчёте и получает сохранённые ID/версию. После ошибки сохранения или удаления черновик не очищается.
- В новые снимки истории включены связанные товары и их цены на момент сохранения. Старые снимки не пересчитываются.

## Проверки

### Материалы прямо в калькуляции — 12 ноября 2026

- Рядом с каждой строкой расхода есть «Изменить», над списком — «+ Добавить материал». Общий редактор позволяет менять название, единицу и закупочную цену, не уходя из расчёта. Те же действия доступны в «Прайсе материалов».
- Цена вводится с точкой или запятой, до четырёх знаков после разделителя, и показывается без округления до копеек. Расход на свечу по-прежнему задаётся отдельно. Изменение общей цены сразу пересчитывает текущую себестоимость и прибыль; введённые количества, название расчёта и привязки товаров не сбрасываются.
- Цены и единицы общие для всех калькуляций; редактор явно сообщает это. Старые снимки истории не меняются. При смене единицы расход нужно привести к новой единице вручную.
- Добавление и редактирование возвращают сохранённый материал с числовым ID и ценой. Клиент применяет его даже при ошибке последующего обновления списка. Ошибка сохранения оставляет черновик, повторный клик не создаёт дубликат; занятое название выдаёт понятную ошибку.
- Пока открыт редактор материала, сохранение снимка калькуляции отключено, чтобы не сохранить расчёт по ещё не применённой цене. Отмена оставляет старый прайс. Новых таблиц и миграций нет.
- Локально прошли 7 UI-проверок калькулятора, lint и production-сборка. В браузере на изолированных тестовых данных проверены редактирование с пересчётом и добавление, включая экран 390 px без горизонтального переполнения. HTTP-сценарий дополнен созданием, переименованием, изменением единицы/цены, проверкой дубликатов и неизменности рецептуры/истории/товаров; его запуск и публикация проверяются отдельно в CI для актуального SHA. Проверка публикации теперь требует маркер нового редактора материалов; наличие коммита в main само по себе не подтверждает обновление Amvera.

Стандартный набор: `npm run lint`, `npm run test:catalog`, `npm run test:ui`, `npm run build:amvera`, `npm run test:http`.

Новые проверки: `node --test tests/costing-ui.test.mjs` и `node --test tests/costing-http.test.mjs`. HTTP-проверка требует production-сборку и отдельную PostgreSQL в TEST_DATABASE_URL. Никогда не направляйте тесты на рабочую базу.

UI-проверки покрывают строковые BIGINT ID, выбор нескольких товаров, сохранение/повторное открытие, независимые цены, поиск, массовый выбор, ошибки и повторный клик. HTTP-проверка покрывает старую схему, миграцию связей, numeric ID, дедупликацию, архивные товары, конфликты версий, неизменность снимков и сохранность товаров. Все эти команды включены в `.github/workflows/catalog.yml`.

## Каталог и учёт торговли — 11 ноября 2026

- Плавающая панель фильтров закреплена на `top: 0`; безопасный отступ устройства перенесён внутрь панели. Верхняя щель больше не открывает фотографии под фильтрами.
- `FormMiniature` общий для фильтра, карточек форм и редактора. Источники: загруженная миниатюра → встроенный портрет → понятная заглушка. Ошибка загрузки изображения включает следующий источник. Старые технические маски больше не используются для миниатюр.
- Из настроек форм удалены силуэт, маска, двухцветность и готовый силуэт «Змея»: владелец работает с готовыми свечами. Сохранение формы не очищает старые поля в базе, фотографии товаров и историю заказов. Миниатюры показываются без перекрашивания и растягивания.
- «Себестоимость» теперь содержит обзор, реестр остатков, журнал расходов и существующие калькуляции. Обзор показывает доступный остаток, резерв, потенциальную выручку, оценку себестоимости и валовой прибыли, заказы, расходы по категориям и выполненные заказы по формам.
- `costing_expenses` — новый журнал с датой, категорией, описанием, суммой, версией и архивированием. Одновременное редактирование защищено проверкой версии; ошибка не очищает черновик. Существующие миграции калькулятора перенесены без изменения в `lib/server/costing.ts`.
- Заказы отбираются **по дате создания, в московском времени**, расходы — по введённой дате; остатки всегда текущие. «Выполнено» означает статус заказа, а не подтверждённую оплату. Потенциальная выручка и прибыль — оценки по текущим ценам и калькуляциям. Расходы журнала показаны отдельно, чтобы не вычесть закупку материалов второй раз.
- Неизвестная себестоимость остаётся пустой: нет калькуляции, несколько связей или незаполненный состав. Эти товары исключены из оценки прибыли и явно перечислены в предупреждении. Резерв не вычитается из остатка повторно. Архивные товары исключены из текущего реестра, скрытые и черновики доступны с отметкой.
- Защищённые административной сессией `/api/admin/reports` и `/api/admin/reports/export` читают согласованный снимок PostgreSQL; экспорт не меняет товары, цены, остатки или заказы. ExcelJS формирует настоящие XLSX с числовыми ячейками, фильтрами и закреплёнными заголовками; текст покупателя не превращается в формулу.
- Выгрузки: общий отчёт (10 листов), остатки с выбранным отбором, себестоимость/состав/материалы/история, заказы и их позиции, расходы. Кнопки есть также в разделах «Остатки» и «Заказы». Подробности: [docs/trade-reports.md](./docs/trade-reports.md).
- Локально прошли lint, production-сборка, 53 UI-проверки, 5 UI-проверок калькулятора, 5 проверок расчётов/XLSX и 35 интеграционных проверок с изолированной PostgreSQL 17.11, без пропусков. В интеграциях проверены права доступа, CRUD расходов, конфликты версий, даты, содержимое XLSX и неизменность товаров/заказов/остатков.

## Публикация и Amvera

Успех Actions и обновление main сами по себе не доказывают развёртывание Amvera. Владелец ранее переподключил репозиторий после ошибки webhook `failed to connect to host`.

После успешных тестов main отдельное задание `Confirm admin on Amvera (read-only)` запускает `scripts/check-costing-publication.mjs`. Оно читает только публичную страницу `/admin` и её статические JS-файлы на домене Amvera, проверяя множественные привязки калькуляций, дашборд, расходы и экспорт, затем проверяет ответ 401 от административных API отчётов. Нет авторизации, записи заказов или изменения рабочих данных. Число попыток ограничено; недоступность домена или старая версия дают отдельную ошибку публикации, не маскируются зелёной сборкой. Это проверка доставки нового интерфейса, а не подтверждение выполнения миграции в рабочей базе.

Фактические результаты проверять для актуального SHA/запуска и нужного домена. Не обещать публикацию без проверки. Историю текущей правки и дальнейшее подтверждение main см. [PR №6](https://github.com/ashinoff/TIXO/pull/6).
