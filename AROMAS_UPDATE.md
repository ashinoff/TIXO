# Аромат для всей коллекции

Покупатель выбирает аромат один раз над каталогом. Все формы остаются на месте
и плавно меняют цвет. В карточках нет отдельных переключателей ароматов.

## Стартовые ароматы

| Цвет | Аромат | Код |
| --- | --- | --- |
| Красный | Вишня и миндаль | `#b82035` |
| Чёрный | Сандал и дым | `#222225` |
| Белый | Белая ваниль | `#f7f5ef` |
| Розовый | Роза и пион | `#e7a0b5` |

Это редактируемые стартовые композиции. Они добавляются автоматически один раз,
при первом обращении к API обновлённого приложения. Существующие ароматы,
карточки, фотографии, заказы и фактические остатки сохраняются. Повторный запуск
не восстанавливает удалённые ароматы и не отменяет редактирование или отключение.
Если название или точный код цвета уже занят, существующая запись сохраняется.

## Админка

В **Ароматах** меняются название, описание, ноты, цвет и доступность. Добавленный
аромат автоматически доступен для всех форм с общим остатком.

В **Формах свечей** задаются название, описание, цена, общий остаток,
публикация и форма для цветового предпросмотра: спираль, колонна, бабл, арка,
ракушка или узел. Фото необязательно. Загруженная фотография остаётся доступна
покупателю по кнопке **Фото формы**. Цветовая модель — предпросмотр, а не
фотография реального изделия; выберите подходящую модель при редактировании.

Остаток формы общий для всех ароматов. Например, остаток 8 означает всего
8 свечей, а не по 8 каждого цвета. Красная и розовая свечи в корзине — отдельные
позиции; их количество проверяется суммарно. Переключение аромата коллекции
не меняет уже добавленные в корзину свечи.

Для заранее отлитых свечей по-прежнему доступен необязательный раздел
**Отдельные остатки по ароматам**. При его использовании распределите количество
по вариантам. Только добавленные и включённые варианты этой формы доступны для
покупки; другие цвета отображаются с кнопкой «Нет в наличии». Старые отдельные
остатки сохраняются. Для вариантов фото также необязательны.

Ошибка одного раздела больше не сбрасывает вход и не мешает загрузке остальных.
В проблемном разделе отображается ошибка и кнопка повторной загрузки. Если
истекла сама сессия, требуется повторный вход. При отсутствии `ADMIN_PASSWORD`
или `SESSION_SECRET` экран входа показывает, какие параметры нужно настроить.

## Amvera

Используются прежние Dockerfile, PostgreSQL и переменные `DATABASE_URL`,
`ADMIN_PASSWORD`, `SESSION_SECRET`, `UPLOAD_DIR`, `PGSSL`. Новые переменные и
ручной SQL не нужны. Миграция добавляет `products.shape`, служебную таблицу
`app_migrations` и четыре стартовых аромата в одной транзакции с блокировкой.

После сборки обновлённого `main` откройте каталог и `/admin`. Проверьте свои
ароматы, фотографии форм и остатки. Для авторизации используйте HTTPS-адрес
приложения: в production cookie входа защищена флагом Secure.

Заказы сохраняют название аромата, цвет и цену на момент покупки. Остатки
резервируются атомарно, повторы заявки с тем же ключом не создают дубликат.
Удаление незавершённого заказа возвращает остатки. Исторические и выполненные
заказы не возвращают уже потраченный запас. Если общий остаток формы после заказа
разделили по вариантам, возврат такого старого заказа требует ручной сверки.

## Проверка

```sh
npm ci
npm test
npm run build:amvera
NODE_ENV=production TEST_DATABASE_URL=postgresql://... npm run test:http
```

`test:ui` проверяет React-компоненты в DOM: общий переключатель, сохранение
выбора в корзине, общий лимит остатков, работу админки при ошибке заказов и
сохранение аромата. Это функциональная проверка, без визуальной проверки CSS.

Для `test:catalog` задайте `TEST_DATABASE_URL`, чтобы включить миграцию,
заказы и конкурентное резервирование в PostgreSQL. Без него запускаются только
проверки входных данных. `test:http` проверяет собранное приложение: вход,
защиту API, сохранение аромата, формы без фото, заказа с двумя ароматами и текста.
Оба серверных набора создают и удаляют собственные схемы `tixo_test_*` / `tixo_http_*`.
GitHub Actions выполняет все наборы на тестовой PostgreSQL 17.5.
