# Ароматы и варианты свечей

## Что изменилось

Вместо настроений на витрине используется общий справочник ароматов. Один аромат
имеет один цвет; одинаковый код цвета нельзя назначить разным ароматам.
Форма свечи хранит название, описание и цену. Для каждого сочетания формы и
аромата задаются фотография, остаток и доступность.

Переключатель в карточке меняет фотографию, название аромата, ноты и подпись цвета.
В корзине разные ароматы одной формы — отдельные позиции. Заказ сохраняет снимок
названия, аромата, цвета, фото и цены: последующее редактирование справочника
не меняет историю заказов.

## Обновление работающего приложения Amvera

1. Перед обновлением сохраните резервную копию PostgreSQL и `/data/uploads`.
2. Разверните проверенный коммит через существующий Dockerfile. Используются те
   же `DATABASE_URL`, `UPLOAD_DIR`, `ADMIN_PASSWORD`, `SESSION_SECRET`, `PGSSL`.
   Новая база и новые переменные не нужны.
3. При первом обращении к API автоматически добавятся `scents`,
   `product_variants` и служебные поля заказов. Миграция выполняется в транзакции
   с блокировкой между экземплярами приложения и допускает повторный запуск.
4. Проверьте, что новая версия обслуживает и витрину, и `/admin`, затем настройте
   реальные ароматы и варианты. Существующие карточки, категории настроений,
   тексты, фотографии и заказы сохраняются. До настройки вариантов карточки
   продолжают продаваться с прежними данными и остатком.

Цвета и ароматы не назначаются автоматически: сведения из старых «настроений»
недостаточны, чтобы определить реальные цветовые варианты вашей коллекции.

## Как настроить коллекцию

1. В `/admin` откройте **Ароматы → Добавить аромат**. Укажите настоящее название,
   описание, ноты, код цвета и понятное название цвета.
2. В **Формы свечей** откройте карточку. Добавьте доступные для неё ароматы.
3. Для каждого варианта загрузите JPG, PNG или WebP до 10 МБ и укажите остаток.
   Для варианта, соответствующего основной фотографии, можно включить
   **Использовать основное фото**. Включённый вариант без фото сохранить нельзя.
4. При первом разделении формы по ароматам распределите фактический остаток
   между вариантами. После этого общий остаток считается автоматически.
5. Сохраните форму. Один и тот же аромат можно добавить в другие формы:
   его цвет и ноты останутся общими для всей коллекции.

Выключенный аромат скрывает связанные варианты на витрине, сохраняя их остатки.
Отдельный вариант можно отключить внутри формы. При нулевом остатке его цвет
виден, но покупка недоступна. Если отключены все варианты, форма не превращается
обратно в товар без аромата.

После изменения цвета в справочнике проверьте фотографии связанных форм:
изображения показывают реальные свечи и не перекрашиваются программно.

## Остатки и заказы

- Новый заказ проверяет цену, доступность и количество на сервере; недоступная
  позиция отклоняет весь заказ, без молчаливого удаления отдельных строк.
- Остатки списываются при создании заявки, в одной транзакции с заказом.
  Строки товаров и вариантов блокируются в согласованном порядке.
- Повторная отправка с тем же идентификатором запроса возвращает существующий
  заказ. Сохранение карточки с устаревшим остатком отклоняется.
- Удаление нового или обрабатываемого заказа возвращает его зарезервированные
  свечи. Удаление выполненного заказа и заказов, созданных до этого обновления,
  не меняет остатки.
- Если исходный вариант уже разделён по ароматам, заказ исходного варианта
  нельзя автоматически вернуть в конкретный цвет: завершите его и вручную
  скорректируйте нужный остаток перед удалением записи.
- Фотографии, заменённые в карточке, сохраняются на диске, поскольку могут
  использоваться в истории заказов.

Подключение онлайн-оплаты этим обновлением не меняется: магазин принимает заявки.

## Проверка

```sh
npm ci
npm run build:amvera
npm run test:catalog
```

Без `TEST_DATABASE_URL` выполняются проверки данных и выбора варианта. Для
проверки миграции, заказов и параллельной покупки последней свечи передайте URL
**тестовой** PostgreSQL. Тест создаёт и удаляет собственную схему `tixo_test_*`.
GitHub Actions запускает эти проверки на PostgreSQL 17.5 и собирает Amvera-версию.

Перед выпуском проверьте на тестовой витрине мобильный каталог, смену фото,
две позиции одной формы с разными ароматами и управление вариантами в `/admin`.

## Откат

До настройки вариантов можно вернуть предыдущую версию приложения: новые
таблицы и поля не мешают старой схеме. После появления вариантов и новых заказов
старый код уже не учитывает их ароматы и правила остатков. Для такого отката
нужен согласованный снимок базы и приложения; не удаляйте новые таблицы отдельно.
